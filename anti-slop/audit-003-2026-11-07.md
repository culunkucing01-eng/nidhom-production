# Antislop Audit: Master Data Mata Pelajaran v1.0

Date: 2026-11-07
Mode: AFTER

## Design Read

An authenticated school-administration screen for finding and managing Arabic and Indonesian subject records. It follows the owner-specified Nidhom v1.0 Modern Institutional and Academic Navy direction. Dials: ENERGY 1, RHYTHM 2, MOTION 1.

Decision notes:

- Shared Nidhom tokens and components preserve the Academic Navy identity and keep this data-management screen consistent with Guru and Kelas.
- Search and status filters precede the table because the primary task is locating a subject record before acting on it.
- The table surfaces Arabic and Indonesian names, active schedule counts, and status because those fields support subject management.
- Native dialogs keep create, edit, detail, and status confirmation focused without adding a route or dependency.

## Findings

### HIGH

#### MAPEL-H01: Interactive targets fall below the 44px minimum

- Rule: R-03
- Files: `apps/web/src/features/admin/AdminTopbar.tsx:57`, `apps/web/src/features/guru/GuruPage.css:16`, `apps/web/src/features/mapel/MapelPage.css:53`, `apps/web/src/features/mapel/MapelPage.tsx:527`
- Evidence: at a 320px viewport, the brand link measured 69x29px; the Edit row action measured 40x44px; and the dialog close target measured 40x44px in the create dialog and 34x44px in the status dialog.
- Impact: undersized hit areas are harder to activate accurately on touch screens.
- Recommendation: set a non-shrinking minimum 44x44px hit area for the brand, row actions, and dialog close control, allowing text or surrounding layout to adapt instead.

#### MAPEL-H02: The brand link has no visible hover or active feedback

- Rule: R-39
- Files: `apps/web/src/features/admin/AdminTopbar.tsx:57`, `apps/web/src/features/guru/GuruPage.css:16`
- Evidence: browser inspection at 320px showed identical brand color, text decoration, and transform at rest and hover (`rgb(23, 43, 77)`, `none`, `none`).
- Impact: pointer users receive no visual signal that the brand link is interactive.
- Recommendation: add restrained hover and active feedback for the Mapel brand link using existing Nidhom tokens, while retaining the keyboard focus indicator.

### MEDIUM

#### MAPEL-M01: The table requires horizontal panning at tablet width

- Rule: R-03
- Files: `apps/web/src/features/mapel/MapelPage.css:2`, `apps/web/src/features/mapel/MapelPage.tsx:322`, `apps/web/src/features/guru/GuruPage.css:310`
- Evidence: at 768px viewport width, the document had no horizontal overflow (`clientWidth` and `scrollWidth` were both 753px), but the table wrapper was 656px wide with `scrollWidth` 860px and `overflow-x: auto`.
- Impact: some columns and row actions are out of view until the user pans the table, which is less discoverable on a tablet.
- Recommendation: provide a tablet-width reflow or reduce the table's minimum width so the principal fields and actions are visible without horizontal panning.

#### MAPEL-M02: Detail terms and definitions are not grouped in a description list

- Rule: R-39
- File: `apps/web/src/features/mapel/MapelPage.tsx:587`
- Evidence: `<dt>` and `<dd>` elements are rendered inside generic `<div>` wrappers, with no enclosing `<dl>`.
- Impact: assistive technology may not receive the intended term-definition grouping for subject details.
- Recommendation: use a `<dl>` as the detail container and retain valid `<dt>`/`<dd>` pairs within it.

### LOW

No additional LOW findings identified in the reviewed Mapel UI.
