# Antislop Audit: Excel Import Readiness

Date: 2026-11-07
Mode: AFTER

## Design Read

The requested screen is an authenticated school-administration workflow for importing and verifying academic records. The existing Nidhom v1.0 Modern Institutional and Academic Navy direction is documented in the previous UI audit and reflected in the shared design tokens. Dials for the requested screen: ENERGY 1, RHYTHM 2, MOTION 1.

No import UI was implemented or visually reviewed in this audit.

## Finding

### HIGH

#### EXCEL-H01: Excel import and import history are not implemented

- Type: requested-scope gap, not a defect in an existing import control.
- Rules: C-2, R-24, R-27.
- Evidence: `apps/web/src/features/admin/AdminTopbar.tsx` declares only Guru, Kelas, and Mapel sections. `apps/web/src/App.tsx` has no schedule, import, history, dashboard, or settings screens. `apps/api/src/index.ts` mounts only auth, guru, kelas, and mapel routes. No import-history table or import endpoint exists in the migrations or routes.
- Impact: there is no way to upload a workbook, inspect or map sheets, see validation results, commit imported rows, search imported schedules, or review import history. The primary acceptance criteria cannot be exercised.
- Recommendation: implement the requested feature as a single audited scope, with backend authorization and validation before wiring the Admin interface. Do not add navigation links until each destination works.

| Same workbook | LogHapus | 3 | includes teacher name, status, schedule details, and notes |
| Same workbook | Absen | 995 | includes teacher name, status, schedule details, and notes |

The permission workbook contains teacher-identifying and attendance/leave-related fields. Treat its contents as personal data. It does not match the requested master-data and schedule import scope and should not be imported without a separately defined permission-data workflow and authorization rules.

The existing schema already has `guru`, `kelas`, `mata_pelajaran`, and `jadwal` tables. `guru.kode` and `kelas.nama` are unique. `mata_pelajaran` has no unique natural key, and `jadwal` has active-slot constraints but no explicit source-row key. Therefore, subject and schedule upsert identity must be resolved explicitly before implementation; relying on generated IDs would duplicate rows on re-import.

## Existing capabilities and implementation surfaces

- Guru, Kelas, and Mata Pelajaran already have authenticated UI screens with search and pagination.
- There is no schedule UI or API route.
- `jadwal_histori` records schedule changes, not workbook import runs.
- The API package contains Hono and Wrangler; the Web package has no Excel parser dependency.
- The local Wrangler config points to `nidhom-api-local`. This audit did not run migrations, write to D1, or access Production.

Files likely involved after approval:

- `apps/api/src/index.ts` and new import/schedule route modules.
- A new local-compatible migration for import-run history and any required natural-key constraints, after confirming the mapping.
- `apps/api/package.json` and lockfile only if a Worker-compatible parser is selected and verified.
- `apps/web/src/App.tsx`, `apps/web/src/features/admin/AdminTopbar.tsx`, a new import and history feature, API client modules, and related styles.
- Existing entity search/API modules only if imported records need additional query/filter coverage.

## Recommended implementation order

1. Confirm workbook-to-schema field mapping and stable identifiers, especially for subjects and schedules.
2. Verify a parser against the Cloudflare Workers runtime and enforce file, sheet, row-count, and type limits on the backend.
3. Add local-only migration and ADMIN-protected preview, validation, import, and history endpoints.
4. Add the Admin upload, sheet selection, mapping, preview, error report, import summary, and history UI using existing Nidhom tokens.
5. Test duplicate re-import, invalid rows, partial failure behavior, authorization, search, responsive layout, and keyboard operation against local D1.
